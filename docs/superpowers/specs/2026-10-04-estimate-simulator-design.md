# 料金シミュレーター 設計

日付: 2026-10-04

## 目的

ポートフォリオ（webhiro.com）に、訪問者が自分で概算金額を出せるページを常設する。狙いは静的サイト・LPコーディング案件の問い合わせを増やすこと。既存の8件のデモはすべて「完成したサイト」なので、訪問者が操作して結果を得る種類のものを1つ足す。

成功の基準は次の3つ。

- 訪問者が種類と数量を選ぶと、内訳と合計がその場で出る
- 出た内訳を持ったまま問い合わせフォームに進める
- 表示される金額が単価マスタ（`~/.claude/data/rate-card.md`）と一致する

## 置き場所と前提

- 新規ページ `/estimate/`（`estimate/index.html`）。ヘッダーのナビに全ページでリンクを足す
- 既存ページと同じく noindex を維持する
- ビルド工程なしの素の JavaScript（ES Modules）。SCSS は既存どおり `sass` CLI でビルドする
- デザインは既存のトークン・書体・配色に従う（Forest Green / Paper / Ink、Fraunces × Shippori Mincho、FLOCSS×BEM）
- 作業は `main` 起点。`netlify` へは一方向マージ。`contact/index.html` の変更はヘッダーのナビへの1行追加だけにとどめ、フォーム部分には触れない

## 入力

1. 種類: 「サイト（複数ページ）」か「LP（1ページ）」の二択。初期値はサイト
2. サイト選択時
   - 下層ページ数（標準）: 0〜30 の整数。初期値 0
   - 下層ページ数（複雑）: 0〜30 の整数。初期値 0
3. LP選択時
   - セクション数: 1〜20 の整数。初期値 10
4. 共通オプション
   - お問い合わせフォーム: 有無
   - スライダー: 0〜10 箇所。初期値 0
   - スクロール演出: 有無
   - 公開作業: 有無

選んでいない種類の入力欄は表示せず、計算にも使わない。範囲外や数値でない入力は、範囲内の最も近い整数に丸める。上限を超える分量は計算できないので、ヒントに「31ページ以上／21セクション以上はご相談ください」と書く。

## 計算

金額はすべて税抜で持つ。

| 項目 | 金額 | 条件 |
|---|---|---|
| トップページコーディング | 30,000円 | サイト選択時に必ず1 |
| 下層ページ（標準） | 10,000円 × 枚数 | サイト選択時 |
| 下層ページ（複雑） | 20,000円 × 枚数 | サイト選択時 |
| LPコーディング | 40,000円 | LP選択時、セクション数 10 以下 |
| LPコーディング（長尺） | 50,000〜60,000円 | LP選択時、セクション数 11 以上 |
| お問い合わせフォーム | 20,000円 | 有のとき |
| スライダー | 5,000円 × 箇所 | 1 箇所以上のとき |
| スクロール演出 | 10,000円 | 有のとき。トップまたはLPの1ページ分 |
| 公開作業 | 5,000円 | 有のとき。用意されたサーバーへのアップロードと表示確認まで |

- 合計は下限と上限の2値で持つ。幅のある項目がなければ両者は同じ値になり、画面では1つの金額として表示する
- 税込は下限・上限それぞれに 10% を加え、1円未満を切り捨てる
- 数量が 0 の項目は内訳に出さない

## 出力

- 内訳の一覧（項目名・数量・金額）
- 税抜合計と税込合計。幅がある場合は「〜」でつないで表示する
- 入力が変わるたびに即時更新する。合計（税抜・税込）は `aria-live="polite"` と `aria-atomic="true"` の領域に出し、内訳の一覧は読み上げ対象に含めない（1文字ごとに全行を読ませないため）
- 注記
  - 「概算です。正式なお見積りは内容を伺ってからお出しします」
  - 含むもの: デザイン再現・レスポンシブ・4ブラウザと実機での確認・画像最適化・各ページ2回までの修正
  - 含まないもの: デザイン制作・WordPress化（別途お見積り）
  - スクロール演出は1ページ分。2ページ以上に入れる場合は別途相談
  - 公開作業は、ご用意いただいたサーバーへのアップロードと表示確認まで。サーバー・ドメインの契約や設定、SSLの有効化、DNS切り替えは別途お見積り

## 問い合わせへの引き継ぎ

- 「この内容で相談する」ボタンを押すと、内訳を文章にして `sessionStorage` に保存し、`/contact/` に移動する。新しいタブやウィンドウで開く操作（Cmd / Ctrl / Shift を押しながらのクリック）のときは保存しない
- `/contact/` では、保存された文章があり、かつお問い合わせ内容欄（`#message`）が空のときだけ、その文章を欄に入れる。入れた後は保存を消す
- 受け渡しはブラウザ内で完結するので、PHP版（main）と Netlify Forms 版（netlify）の両方で同じコードが動く
- 流し込みの処理は、全ページで読み込まれている `assets/js/main.js` から呼ぶ。`#message` がないページでは何もしない

流し込む文章の形式:

```
【料金シミュレーターの結果】
種類: サイト（複数ページ）
・トップページコーディング ×1 30,000円
・下層ページ（標準） ×4 40,000円
・お問い合わせフォーム 20,000円
概算合計: 90,000円（税抜）／99,000円（税込）
```

## ファイル構成

| ファイル | 役割 |
|---|---|
| `estimate/index.html` | 画面 |
| `assets/js/component/estimate-calc.js` | 入力値を受け取り、内訳と合計（下限・上限・税込）を返す。DOM に触れない |
| `assets/js/component/estimate-form.js` | フォームの読み取り、丸め、表示の更新、ボタンの処理 |
| `assets/js/component/estimate-handoff.js` | 内訳の文章化、`sessionStorage` への保存と取り出し、問い合わせ欄への流し込み |
| `assets/js/main.js` | 上記の初期化を追加する |
| `assets/scss/page/estimate/` | ページ固有のスタイル。`page/_index.scss` に登録する |
| 各ページの HTML | ヘッダーのナビにリンクを追加する |

単価は `estimate-calc.js` の先頭に定数としてまとめる。画面の選択肢には金額を書かず、金額は計算結果としてだけ表示する。単価マスタを改定したときに直す場所は、この定数と `estimate/index.html` の `<noscript>` 内の単価表の2か所。

## エラー処理

- 入力の丸め（範囲外・非数値）だけを扱う
- `sessionStorage` が使えない環境では、読み書きを try/catch で囲み、失敗時は引き継ぎなしで `/contact/` に移動する
- JavaScript が無効な環境向けに、`<noscript>` で主要4項目の単価表を出し、動かない入力欄と結果の箱は表示しない

## テスト

- `estimate-calc.js` は Node 標準のテスト機能（`node --test`）で確かめる
  - サイト: トップのみ／下層の標準と複雑の組み合わせ
  - LP: セクション数 10 と 11 の境界
  - オプション: フォーム・スライダー・演出・公開作業の加算、スライダー 0 箇所で内訳に出ないこと
  - 幅のある合計の下限と上限、税込の切り捨て
- 文章化（`estimate-handoff.js` の文字列を作る部分）も同じ方法で確かめる
- 画面はブラウザで操作して確かめる: 種類の切り替え、即時更新、問い合わせ欄への流し込み、欄に入力済みのときに上書きしないこと、キーボードだけでの操作、スマホ幅での表示

## 入れないもの

- 納期の表示。想定作業時間は実測ではないので、根拠のない日数は出さない
- デザイン制作・WordPress の金額。単価が未定なので注記にとどめる
- サーバー・ドメインの契約や設定、DNS切り替えの金額。相手の環境で作業量が大きく変わるので注記にとどめる
- 見積り結果の保存、URL での共有、PDF 出力

## 単価マスタとの関係

スライダー 5,000円/箇所、スクロール演出 10,000円/ページ一式は 2026-10-04 に、公開作業 5,000円/式は 2026-10-05 に決めた値で、単価マスタではまだ空欄になっている。実装とあわせて単価マスタにも記入する。

公開作業の根拠（2026-10-05 調査）: コーディング代行会社の料金表では、静的サイトの公開作業は 0円（ファストコーディング）、10,000円〜（コーディングラボ）、15,000円（コーディングベア）。サーバー設定やDNS切り替えは各社とも 20,000円以上の別項目。個人のフリーランスの価格は資料が少なく確かめきれていない。5,000円は下限時給 2,000円 × 想定 2.5時間で、作業範囲をアップロードと表示確認に限ることが前提。
